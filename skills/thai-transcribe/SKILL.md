# ถอดเสียงภาษาไทยเป็นข้อความ

ระบบทำงานในเครื่อง และไม่ส่งไฟล์เสียงออกไปนอกเครื่อง ใช้ได้ทั้ง Windows, macOS และ Linux

สคริปต์อยู่ในโฟลเดอร์ `scripts/` ภายใน base directory ของสกิลนี้ ซึ่งระบบจะแสดงให้เห็นตอนที่โหลดสกิล:
- `transcribe.py` ถอดเสียงจากไฟล์เสียงหรือวิดีโอ
- `keyframes.py` ดึงภาพหน้าจอจากวิดีโอ
- `align.py` หาเวลาคลาดระหว่างไฟล์อัดสองไฟล์ของประชุมเดียวกัน
- `report.py` สร้างรายงานประชุม ถ้าเป็นไฟล์วิดีโอ ให้ดูหัวข้อ [ไฟล์วิดีโอ](#ไฟล์วิดีโอ-ภาพหน้าจอ--รายงานประชุม)

## การติดตั้ง

ไม่ต้องติดตั้งเอง สคริปต์จัดการให้ในการรันครั้งแรก:
- สร้าง venv และติดตั้ง faster-whisper กับ Pillow ไว้ที่ `$THAI_TRANSCRIBE_HOME` ค่าเริ่มต้นคือ `~/.thai-transcribe`
- ดาวน์โหลดโมเดลที่เลือกครั้งเดียว: `fast` 1.6 GB, `accurate` 1.5 GB

สิ่งที่ต้องมี:
- Python 3.9 ขึ้นไป
  - Windows ใช้ `python` หรือ `py -3`
  - macOS และ Linux ใช้ `python3`
- พื้นที่ว่างราว 2–4 GB

ก่อนรันครั้งแรก ให้ตรวจพื้นที่ว่างในไดรฟ์ของโฟลเดอร์ home
- ถ้าเหลือน้อยกว่า 5 GB ให้ถามผู้ใช้ว่าจะเก็บไว้ที่ไหน
- จากนั้นตั้ง env `THAI_TRANSCRIBE_HOME` ให้ชี้ไปที่นั่น โดยใส่ใน `env` ของ `~/.claude/settings.json` ทุกคำสั่งจะได้ใช้ค่าเดียวกัน

## วิธีรัน

```bash
# Windows
python "<skill-dir>/scripts/transcribe.py" "<ไฟล์เสียง>"
# macOS: caffeinate -i กันเครื่องหลับระหว่างรัน (ถ้าเป็นโน้ตบุ๊ก ต้องเสียบสายชาร์จด้วย)
caffeinate -i python3 "<skill-dir>/scripts/transcribe.py" "<ไฟล์เสียง>"
# Linux
python3 "<skill-dir>/scripts/transcribe.py" "<ไฟล์เสียง>"
```

บน macOS:
- รันบน CPU ได้ทั้ง Intel และ Apple Silicon (M1–M4) แต่ยังไม่รองรับ GPU ของ Mac
- ถ้ายังไม่มี `python3` ให้ผู้ใช้รัน `xcode-select --install` หรือติดตั้งผ่าน Homebrew ด้วย `brew install python`

ตัวเลือก:
- `--model` เลือกโมเดล ตัวเลขด้านล่างวัดบน CPU Ryzen 5 4500U แบบไม่มี GPU:

  | ค่า | โมเดล | ความเร็ว | ความผิดพลาด (CER) |
  |---|---|---|---|
  | `fast` (ค่าเริ่มต้น) | Thonburian distill large-v3 | ราว 1 เท่าของเวลาจริง | ราว 2% |
  | `accurate` | Thonburian medium | ราว 0.7 เท่าของเวลาจริง | ราว 0.4% |

  - รอบทดสอบจริงกับไฟล์ประชุม 2 ชม. 10 นาที: `fast` ใช้ 1 ชม. 30 นาที ส่วน `accurate` ใช้ 1 ชม. 45 นาที
  - `accurate` ถอดตามเสียงพูดจริงทุกคำ คำพูดซ้ำอย่าง "แต่แต่" จึงติดมาด้วย
- `--suffix <ชื่อ>` บันทึกผลเป็นไฟล์ใหม่ชื่อ `<ชื่อไฟล์>.<ชื่อ>.txt` ใช้ตอนถอดซ้ำแบบที่ไม่ต้องการแตะไฟล์เดิม เช่น `--model accurate --suffix accurate`
- `--out-dir <โฟลเดอร์>` เลือกที่เก็บผลลัพธ์ ค่าเริ่มต้นคือโฟลเดอร์เดียวกับไฟล์เสียง
- `--device cuda` ใช้การ์ดจอ NVIDIA ถ้ามี จะเร็วขึ้นมาก แต่ต้องมีไลบรารี CUDA 12 และ cuDNN
- `--window` ความยาวสูงสุดต่อการถอดหนึ่งครั้ง ค่าเริ่มต้น 20 วินาที **ห้ามตั้งเกิน 20**
  - โมเดลภาษาไทยจะหยุดถอดเมื่อเสียงพูดต่อเนื่องเกินราว 20 วินาที ข้อความส่วนที่เหลือจะหายไปเงียบๆ
  - จากการวัด หน้าต่าง 28 วินาทีทำให้ข้อความหายราว 24%
- `--restart` เริ่มใหม่ตั้งแต่ต้น โดยไม่สนใจความคืบหน้าที่บันทึกไว้
- `--overwrite` อนุญาตให้เขียนทับไฟล์ผลลัพธ์ที่มีอยู่แล้ว
  - ถ้าไม่ใส่ตัวเลือกนี้ สคริปต์จะไม่ยอมเขียนทับไฟล์ที่มีอยู่
  - **ห้ามใช้ ถ้าผู้ใช้ไม่ได้สั่งให้เขียนทับเองอย่างชัดเจน**
- `--setup` ติดตั้งอย่างเดียวแล้วจบ ไม่ถอดเสียง

ผลลัพธ์จะอยู่ข้างไฟล์เสียง:
- `<ชื่อ>.txt` ข้อความล้วน แบ่งเป็นย่อหน้า
- `<ชื่อ>.timestamped.txt` แต่ละบรรทัดเป็น `[HH:MM:SS] ข้อความ` ของเสียงพูดหนึ่งท่อน ยาวไม่เกิน 20 วินาที

## ขั้นตอนที่ Claude ต้องทำ

1. ตรวจว่าไฟล์มีอยู่จริง ถ้าผู้ใช้ส่งมาหลายไฟล์ ให้รันทีละไฟล์ต่อกัน ห้ามรันพร้อมกัน
2. รันคำสั่งด้วย `run_in_background: true` ทุกครั้ง เพราะไฟล์ยาวอาจใช้เวลาหลายชั่วโมง
   - ถ้ากรอง output ด้วย grep ต้องใส่ `--line-buffered` ไม่อย่างนั้นความคืบหน้าจะไม่แสดงจนกว่างานจะจบ
   - ก่อนรัน ให้บอกผู้ใช้ให้เสียบสายชาร์จ ไม่ให้เครื่อง Sleep และไม่ปิดหน้าต่างนี้
3. ติดตามความคืบหน้าจากไฟล์ output ของ background task
   - ทุกราว 1 นาทีจะมีบรรทัด `ท่อน x/N [ตำแหน่งในไฟล์] · ผ่านไป … · คาดว่าเหลือ ~…`
   - เมื่อเห็นบรรทัดแรก ให้แจ้งผู้ใช้ว่าน่าจะเสร็จราวกี่โมง
   - ผู้ใช้เปิดดูไฟล์ `.txt` ระหว่างที่ยังรันได้ เพราะไฟล์จะอัปเดตทุก 10 ท่อน
4. ถ้างานหยุดกลางทาง ให้รันคำสั่งเดิมซ้ำ
   - สคริปต์จะอ่าน `<ชื่อ>.progress.json` แล้วทำต่อจากท่อนที่ค้างไว้
   - ไฟล์นี้จะถูกลบเองเมื่อถอดเสร็จ
5. เมื่อเสร็จ ให้แจ้ง path ของไฟล์ผลลัพธ์ ยกตัวอย่างข้อความช่วงต้นสัก 5–10 บรรทัด และบอกเวลาที่ใช้จริง
6. ห้ามลบหรือเขียนทับไฟล์ transcript ที่มีอยู่ ถ้าจะถอดใหม่ให้ใช้ `--suffix`

## ไฟล์วิดีโอ: ภาพหน้าจอ + รายงานประชุม

ไฟล์เสียงให้ถอดเป็นข้อความตามขั้นตอนด้านบนเหมือนเดิม ส่วนนี้เป็นทางเลือกเพิ่มสำหรับไฟล์วิดีโอเท่านั้น

ถ้าผู้ใช้ส่งไฟล์วิดีโอมา (.mp4, .webm, .mov, .mkv) และยังไม่ได้บอกว่าต้องการอะไร **ให้ถามก่อน** ว่าจะเลือกแบบไหน:
- **ข้อความอย่างเดียว:** รัน `transcribe.py` กับไฟล์วิดีโอได้ตรงๆ เหมือนไฟล์เสียง
- **ข้อความ + ภาพหน้าจอ + รายงานประชุม:** ทำตามขั้นตอนด้านล่างทั้งหมด

ถ้าผู้ใช้บอกมาแล้ว เช่น "ถอดพร้อมภาพสไลด์" หรือ "เอาแค่ข้อความ" ก็ทำตามนั้นได้เลยโดยไม่ต้องถามซ้ำ

1. **ดึงภาพหน้าจอ (เร็ว ให้ทำก่อน):**
   ```bash
   python "<skill-dir>/scripts/keyframes.py" "<วิดีโอ>"
   ```
   - ได้โฟลเดอร์ `<ชื่อ>.frames/` ข้างไฟล์วิดีโอ มีภาพ JPEG และ `index.json`
   - วิธีจับภาพ: บันทึกเมื่อภาพนิ่งแล้วและต่างจากภาพล่าสุด เช่น เปลี่ยนสไลด์ หรือเปลี่ยนหน้าที่แชร์ ส่วนการสลับระหว่างกล้องกับจอแชร์ จะบันทึกด้วยเกณฑ์การเปลี่ยนฉากใหญ่
   - ภาพจากกล้องที่ขยับตลอดเวลาจะไม่ถูกบันทึกซ้ำ
   - **ช่วงที่จอเปลี่ยนรัวๆ** เช่น สลับหน้าต่างไปมา หรือแก้ Google Sheet สด จะเก็บแค่ภาพสุดท้ายหลังจอนิ่งแล้ว 6 วินาที (`--settle`)
   - **ถ้าได้ภาพน้อยเกินไป:** ลด `--change` เช่น 0.01
     - ค่าเริ่มต้นคือ 0.02 หรือ 2% ของภาพ
     - การคลิกเปลี่ยนช่องใน Sheet หรือเลื่อนเมาส์เปลี่ยนภาพราว 0.7% จึงไม่ถูกนับ
   - **จำนวนภาพสูงสุดคือ 60** (`--max-frames`): ถ้ามีภาพที่เข้าเกณฑ์มากกว่านั้น ระบบจะตัดภาพที่ "ใหม่น้อยที่สุด" ออก
     - ภาพแรกของวิดีโอและภาพตอนเปลี่ยนฉากใหญ่จะเก็บไว้เสมอ
     - ตัวอย่าง: ประชุมที่แก้ Google Sheet สด 2 ชั่วโมงได้ภาพเข้าเกณฑ์ 342 ภาพ
     - ถ้าผู้ใช้อยากได้ละเอียดกว่านี้ ให้เพิ่มค่านี้ หรือใส่ 0 เพื่อไม่จำกัดจำนวน
   - **ใช้ `--overwrite` เฉพาะเมื่อผู้ใช้สั่ง**
2. **ถอดเสียง:** ใช้ `transcribe.py` กับไฟล์วิดีโอได้โดยตรง และรันแบบ background ตามขั้นตอนด้านบน
   - **ห้ามรันพร้อมกับ keyframes** บนเครื่องที่สเปกไม่สูง เพราะจะแย่ง CPU กัน
   - **ถ้ามี transcript ของประชุมนี้อยู่แล้วจากไฟล์เสียงอีกไฟล์ ไม่ต้องถอดใหม่:**
     - ไฟล์เสียงกับไฟล์วิดีโอมักเริ่มอัดคนละเวลา จึงต้องหาค่าคลาดก่อน คำสั่งนี้ใช้เวลาไม่ถึงนาที:
       ```bash
       python "<skill-dir>/scripts/align.py" "<ไฟล์เสียงที่ใช้ถอด>" "<วิดีโอ>"
       ```
     - ถ้าความมั่นใจมากกว่า 8 ให้ใส่ `--offset <ค่าที่ได้>` ตอนรัน report.py
     - ถ้าความมั่นใจต่ำกว่านั้น ให้ถอดจากไฟล์วิดีโอใหม่
3. **อ่านภาพ:** ใช้ Read tool เปิดภาพใน `.frames/`
   - ถ้ามีภาพไม่เกิน 60 ภาพ (ค่าเริ่มต้น) ให้ดูทุกภาพ
   - ถ้ามากกว่านั้น ให้เลือกดูภาพที่ค่า `diff` ใน index.json สูง และกระจายให้ครอบคลุมทั้งวิดีโอ
   - **ภาพหน้าจอที่แชร์อาจมีข้อมูลส่วนตัวติดมา** เช่น แชต อีเมล หรือแท็บอื่น ถ้าเห็น ให้เตือนผู้ใช้ก่อนส่งรายงานต่อให้คนอื่น และไม่ต้องคัดลอกข้อมูลพวกนั้นลง notes
   - เขียน `<ชื่อ>.notes.json` ข้างไฟล์วิดีโอ เก็บหัวข้อสั้นของแต่ละภาพ:
     ```json
     {"0003_00-12-30.jpg": "สไลด์: แผนงาน Q4", "0004_00-15-02.jpg": {"title": "แชร์จอ: หน้าระบบหลังบ้าน", "note": "ปุ่ม export อยู่มุมขวาบน"}}
     ```
4. **เขียนสรุป:** สร้าง `<ชื่อ>.summary.md` จากทั้งข้อความและภาพ ให้มีหัวข้อดังนี้:
   - ประเด็นหลัก
   - สิ่งที่ตกลงกัน
   - งานที่ต้องทำ พร้อมผู้รับผิดชอบ ถ้ามีคนพูดถึง
   - คำถามที่ยังค้างอยู่
5. **สร้างรายงาน:**
   ```bash
   python "<skill-dir>/scripts/report.py" "<วิดีโอ>" --notes "<ชื่อ>.notes.json" --summary "<ชื่อ>.summary.md"
   ```
   - ได้ไฟล์ `<ชื่อ>.report.html` เปิดในเบราว์เซอร์ได้เลย
   - ในหน้ามีตัวเล่นวิดีโอ กดเวลาที่ไหนก็ข้ามไปเล่นตรงนั้น ภาพแต่ละภาพจับคู่กับสิ่งที่พูดในช่วงนั้น
   - สั่งพิมพ์เป็น PDF ได้
   - รายงานอ้างถึงวิดีโอและภาพแบบ path สัมพัทธ์ ต้องเก็บไฟล์ทั้งหมดไว้ด้วยกัน
   - **ห้ามเขียนทับรายงานเดิม** ถ้าต้องสร้างใหม่ ให้ใช้ `--out <ชื่อใหม่>.report.html`
6. **ส่งผลให้ผู้ใช้:** แจ้ง path ของรายงาน จำนวนภาพ และสรุปสั้นๆ

## ข้อควรรู้
- ชื่อเฉพาะ ศัพท์เทคนิค และคำภาษาอังกฤษที่พูดปนอาจสะกดผิด ถ้าผู้ใช้ให้ช่วยเกลา Claude แก้ได้จากบริบท แต่ต้องบอกผู้ใช้ว่าแก้ตรงไหน
- โมเดลไม่ได้ใส่เครื่องหมายวรรคตอนหรือแยกผู้พูด (ไม่มี speaker diarization)
- ห้ามแก้ `compression_ratio_threshold=None` ในสคริปต์
